A calm, focused desktop workspace for planning and tracking projects. Plan with AI, inspect your local code, and keep the board moving.

## Features

- **Kanban board**: drag cards between columns and reorder them manually. Long-press or flick to grab a card; a drop placeholder shows exactly where it will land. Four statuses by default, with optional Backlog and In review.
- **Views**: Board, paginated List, Roadmap, and Workload views per project, plus search and filters on the board.
- **AI planning**: describe what you want and generate a spec, user stories, and a task backlog with estimates, priorities, and assignees. Drafts are resumable, editable, and refinable, and publish straight to the backlog.
- **Repository awareness**: connect a local or WSL repository per project. The AI reads a cached index (file tree, symbol map, and relevant code hunks) to explain tasks, check whether they are implemented, and produce review notes.
- **Task chat**: streamed, persistent per-task conversations with follow-ups, markdown rendering, code copy buttons, and a model picker.
- **Working calendar**: per-project working hours and workdays drive realistic due dates when tasks move into progress.
- **Workspaces**: everything lives inside a workspace. Switch, create, rename, and delete workspaces with image icons from the sidebar.
- **PDF reports**: styled, well-structured exports for drafts and published projects, grouped by task status.
- **Self-updates**: the app checks GitHub for new releases and offers one-click updates with automatic restart and database migrations.

## Getting started

### Prerequisites

- Node.js 20 or newer
- Rust stable (rustup)
- Platform prerequisites for Tauri 2: [system dependencies](https://v2.tauri.app/start/prerequisites/)

### Install and run

```sh
npm install
npm run tauri dev
```

The frontend runs on port 1420 in development and is built to `build/` for production.

### Scripts

| Script | Purpose |
| --- | --- |
| `npm run dev` | SvelteKit dev server |
| `npm run check` | Type-check with svelte-check |
| `npm run build` | Build the static frontend |
| `npm run tauri dev` | Run the desktop app in development |
| `npm run tauri build` | Build the release bundles |

## Releasing

Releases are triggered by pushing a Git tag. The app version is derived from the tag.

```sh
git tag v1.2.3
git push origin v1.2.3
```

The `Release` workflow builds unsigned bundles for Windows, Linux, and macOS, attaches them to a draft GitHub release, and publishes `latest.json` for the update system.

Update signatures use minisign. The public key is baked into the app; the private key must be available when bundling. Configure this repository secret:

- `TAURI_SIGNING_PRIVATE_KEY`: the contents of your private key file (see `src-tauri/.updater-key`, generated by `npx tauri signer generate --ci -w src-tauri/.updater-key`). Keep this file out of Git.

For local production builds, export the same environment variable before running `npm run tauri build`. Without the private key, the build fails because updater artifacts are enabled.

The generated key has no password, so no password environment variable is set anywhere. If you regenerate the key with a password (`-p`), set `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` locally and add it as a secret plus the matching env in `.github/workflows/release.yml`.

The update checker in the sidebar reads the latest release from `danielkosgei/workmaster`. Update the repository constant in `src/lib/update.ts` if you fork this project.

## Project structure

```
src/                 Svelte frontend (SvelteKit)
  lib/               Store, AI client, repo scanner, PDF, components
  routes/            Pages: dashboard, projects, tasks, team, activity, settings
src-tauri/           Tauri shell (Rust)
  src/lib.rs         App setup and SQL migrations
  capabilities/      Permissions for plugins
  icons/             App icons
.github/workflows/   CI and release pipelines
```

## Data

All data lives in a single SQLite database (`workmaster.db`) on the local machine. Database migrations run automatically at startup, including after an in-app update.
